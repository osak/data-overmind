AI Doc Template レビューフィードバック機能

人間の段落コメントを安全に保存し、AI が元文書と対応づけて修正できる仕組みの実装計画。

開発者・レビュアー

ai-doc-template の文書に段落単位のコメント UI を加え、data-overmind が元 HTML の隣へレビュー JSON を安全に保存します。文書の通常配布や印刷は変えず、data-overmind 経由で開いたときだけレビュー機能が現れます。

2 つのリポジトリは同一オリジンの小さな HTTP API で接続します。HTML は改変せず、architecture.html に対して architecture.html.review.json を 1 個だけ作る方式を採用します。

実現する体験

  1. 人間が data-overmind から HTML を開きます。
  2. 段落右側の薄い三点リーダーからコメント欄を開きます。
  3. 入力は自動的にブラウザへ一時保存されます。
  4. 目次メニューの「レビューをサブミットする」で送信します。
  5. 元 HTML と同じ場所にレビュー JSON が保存されます。
  6. AI は HTML と JSON を読み、引用された段落へ修正を適用します。

重要な設計判断

data-overmind 上でだけ自動有効化する

doc.js は同一オリジンの /_data-overmind/review-context を確認します。成功した場合だけ UI を生成し、404 や直接ファイル表示では何も追加しません。既存の静的配布、単一ファイル配布、印刷を壊しません。

元 HTML は変更しない

レビュー提出時に HTML へリンクやメタデータを書き戻すと、元文書の hash が変わり、編集中の差分とも衝突します。代わりに、決定的な sibling filename と JSON 内の source.path で双方向に辿れるようにします。

JSON を正本にする

Markdown よりも、再読込、入力検証、競合検出、将来の状態追加が安定するため JSON を選びます。2 space indent と明示的なフィールド名により AI もそのまま読めます。

読み取り専用境界を必要最小限だけ広げる

一般的なファイル書き込み API は作りません。保存先はサーバーが元 HTML の basename から導出し、その sibling review file だけを書き換えられるようにします。

保存される情報

各コメントには、コメント本文だけでなく、対象の段落またはリスト項目を再発見するための複数の手掛かりを保存します。

  • 直前の見出し ID。
  • 文書全体とセクション内の段落位置。
  • 空白を正規化し API 上限内に収めた段落引用。
  • 保存時にサーバーが引用から計算する SHA-256。
  • 任意の明示 data-review-id。

API

コンテキスト取得

GET /_data-overmind/review-context?document=/docs/architecture.html は、元 HTML の hash、保存先 review path、既存レビューと revision を返します。HTML でないファイルやルート外の path は拒否します。

レビュー保存

PUT /_data-overmind/reviews?document=/docs/architecture.html が現在の全コメントを保存します。決定的なリソースの置換なので、再実行可能な PUT を使います。

競合

元 HTML の hash または既存 review revision が画面を開いた時点から変わっていた場合は 409 Conflict とし、ファイルを変更しません。画面側は draft を残したまま再読み込みを促します。

JSON と専用 header を必須にし、cross-origin request を拒否します。body は 1 MiB、コメントは 500 件、1 コメントは 16 KiB に制限します。一時ファイルを同じディレクトリへ書き、同期後に rename して原子的に置換します。

レビュー UI

段落の操作

未コメントの三点ボタンは薄く、段落への hover または focus で明瞭になります。コメントがある段落では常時見える状態にします。パネルは同時に 1 個だけ開き、Escape で閉じて元のボタンへフォーカスを戻します。

目次メニュー

目次の下にコメント件数、自動保存状態、submit ボタン、送信結果を表示します。短い文書で目次が作られなくても、このレビュー領域だけは表示できるようにします。

draft の保護

入力は約 300 ms の間隔で localStorage に保存します。blur、タブが非表示になる時、ページ離脱時にも保存します。キーへ元 HTML の hash を含め、文書更新後に古い draft を誤適用しません。

実装結果

  1. JSON schema、context / save API、入力検証を実装しました。
  2. source / review の競合検出と atomic write を実装しました。
  3. 機能検出、段落アンカー、コメント UI、localStorage を追加しました。
  4. dark、mobile、keyboard、print を調整しました。
  5. Go テスト、standalone build、実ブラウザでの一連の操作を確認しました。

受け入れ条件

  • 全段落からコメント入力を開始できる。
  • reload や submit 失敗で draft が失われない。
  • sibling review JSON が原子的に保存される。
  • source / review の競合で上書きしない。
  • API がない環境で既存表示が回帰しない。
  • keyboard、mobile、dark、print で利用できる。
  • AI が quote と comment から修正対象と要求を理解できる。

対象外と将来拡張

初版では単一レビュアー、HTML ごとに 1 review file、対象は p と li です。返信、履歴、承認、表や図へのコメント、AI タスクの自動起動は将来拡張とします。

将来はコメント状態、複数レビュー、レビュー一覧、表・図・コードへのアンカーを schema version または後方互換フィールドで追加できます。初版の companion naming と source identity は維持します。
